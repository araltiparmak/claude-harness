# D2

Read when the diagram is `.d2`: architecture, nested groups, AWS icons, message routes.

## Layout

- `render.sh` uses the source's `vars: { d2-config: { layout-engine: elk } }` when it has one, TALA otherwise; `D2_LAYOUT=elk|dagre|tala` overrides both for one run. It prints the PNG's size and aspect, and a `WIDE` line when it breaks the aspect rule: fix that before reading the PNG.
- A nested group's own `direction` works only under TALA. ELK and dagre ignore it and stack everything, so the picture goes very tall or wide. Without TALA, shape the picture with the parent's `direction` alone. Even TALA takes it as a hint: a fan-out inside a group can spread around its hub instead of running in a row. A route that must read strictly left to right uses ELK (Message chains).
- Set a note or label only as wide as its box.
- Define `classes` (one fill per component type) instead of per-node styles.
- `SKETCH=1 scripts/render.sh <file.d2>` draws the same source hand-drawn, with a handwriting font, like a whiteboard. Layout, classes and icons are unchanged. Use it when the user asks for a sketch, Excalidraw or whiteboard look, or when the picture is a draft for discussion.

## AWS icons

D2 draws the official AWS icons from local copies, so a render needs no network after the first run.

- Write `icon: ICONS/aws/<name>.svg`. `render.sh` swaps `ICONS/` for the skill's `icons/` folder, and runs `scripts/fetch-icons.sh` first when icons are missing. Plain `d2` does not know `ICONS/`, so render through `render.sh`.
- Names in `scripts/icons.tsv`: `lambda`, `ecs`, `fargate`, `ec2`, `api-gateway`, `cloudfront`, `route53`, `vpc`, `alb`, `waf`, `cognito`, `secrets-manager`, `sqs`, `sns`, `eventbridge`, `step-functions`, `dynamodb`, `rds`, `aurora`, `s3`, `kinesis`, `cloudwatch`.
- Another service: add a line `name<TAB>Category%2FIcon-Name` to `icons.tsv`, run `scripts/fetch-icons.sh`. The path is the one on `icons.terrastruct.com/aws%2F...`; a wrong name returns 403 and the script reports it. Spaces are `%20`, `&` is `%26`, `,` is `%2C`, `/` is `%2F`.
- The icons are not in git (`icons/` is ignored): AWS owns them, and this repo is public. A new machine fetches them on the first render.
- Use a class for icon nodes: `shape: image`, `width: 80`, `height: 80`, `label.near: outside-bottom-center`. The label then sits under the icon and no edge runs through it.
- Group by tier (request path, async path), each tier a nested group with its own `direction: right`, and stack the tiers with `direction: down` on the parent (TALA). One long row of icons comes out wider than 4:1; one long column comes out narrower than 1:1.
- Colours come from the icons, so keep the groups and edges quiet.

## Message chains

Services that hand a message along are two questions, so draw two pictures:

1. **The route** (which service sends to which, through which topic and queue): D2 with ELK, left to right (`examples/message-chain.d2`). Services are plain boxes; topics, queues and DynamoDB tables are icon nodes.
   - Put `vars: { d2-config: { layout-engine: elk } }` above `direction: right`. ELK places every node one column right of what feeds it, so a consumer always stands right of the service whose topic it reads, and consumers of the same topic stand in one column, in parallel. TALA treats direction as a hint and scatters a fan-out.
   - The usual shape is SNS to SQS: a few topics, each carrying several message types, and every consumer reading from its own queue subscribed to a topic. A topic never points straight at a service.
   - Label the publish edge with the message types the producer sends, and each subscription edge with the types that queue listens to.
   - A service's DynamoDB table sits to its right.
   - Show a failure path as a dashed edge from the queue to a red dead-letter box.
   - One route per topic. A chain through two topics comes out about 4:1 even with ELK. A topic a consumer publishes to ends the picture as an icon node; its subscribers get their own route, and the sequence shows the whole chain.
2. **One message over time** (order, retries, who waits): a Mermaid `sequenceDiagram` with `autonumber` (see `mermaid.md`). Topics and queues are participants.

Put the route first. Add the sequence only when order, retries or failures matter. Do not draw both in one picture.
